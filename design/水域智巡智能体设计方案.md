# AI智能体设计方案

作品名称：水域智巡——基于YOLO与Qwen的水域综合异常识别智能体

## 一、需求与痛点分析

### 1.1 业务背景

河湖、水库、岸线和近岸水域的日常巡查会产生大量图片。传统流程往往由业务人员收集图片，再交给熟悉算法环境的技术人员启动模型、整理结果并编写说明。模型即使具备识别能力，普通巡查人员仍需要理解命令行、权重文件和结果格式，形成“算法可用但业务难用”的最后一公里问题。

本作品面向水域治理线索初筛，把图像分类模型封装为智能体可调用的视觉工具。用户只需上传图片并用自然语言提问，智能体即可完成输入校验、视觉识别、风险复核判断、自然语言解释和脱敏审计。系统服务的是辅助研判，不替代现场核查、执法认定或专业人员最终决策。

### 1.2 核心痛点

- 操作门槛高：传统模型需要专业人员配置环境、选择权重并执行推理命令。
- 结果难解释：裸模型通常只返回类别和概率，业务人员还需要理解风险和下一步动作。
- 长尾风险高：官方 1,144 张训练图片中“有漂浮物”占 1,026 张，而“乱建”和“正常”仅 4 张、7 张，单看 Accuracy 会掩盖少样本类别风险。
- 服务不稳定：远程大模型可能超时或短暂不可用，不能因此丢失本地视觉识别结果。
- 证据链不足：如果不记录模型版本、工具步骤和耗时，难以复核某次结论的来源。
- 交付易泄密：原始资料、测试图片、API Key、日志和训练缓存若被整目录压缩，可能造成合规风险。

### 1.3 目标与范围

首版覆盖两条共享模型、不同交互方式的业务链：一是面向普通用户的受控多工具智能体；二是面向初赛打榜的确定性批量图片分类与官方格式 JSON 生成。交互端支持图片异常识别、巡查报告、结果可靠性说明和无图片的类别知识咨询；识别类别严格限定为乱采、乱建、乱堆、乱占、有漂浮物和正常。

官方只提供整图单标签，没有边界框或分割标注，因此当前视觉能力是 YOLO 图像分类（YOLO-CLS），不宣称输出异常位置、数量、面积或严重度。视频、监控流、多源遥感、相似案例检索和主动学习属于可沿工具接口扩展的后续能力，不阻塞首版交付。

### 1.4 验收目标

有效图片应在一次交互内得到六类之一、置信度、Top-3、复核提示、任务计划、工具轨迹和依据说明；无效文件应在模型调用前被拒绝。Qwen 故障时保留视觉结果并明确显示确定性回退。批量链应生成与官方 `train.json` 同 Schema 的结果，并在归档前通过结构、敏感文件和 JSON 校验。

## 二、智能体总体架构设计

### 2.1 设计原则

- 决策可控：YOLO 是分类结论的唯一来源；Qwen 只能提出通过Schema校验的任务计划并基于证据生成报告，不改写标签。
- 两链同源：单图智能体和批量提交共用四折分类器、类别枚举与结果 Schema。
- 故障隔离：视觉、本地复核策略、Qwen 解释和审计分别记录状态，局部故障不吞掉核心结果。
- 最小暴露：图片只在请求期间处理；审计不保存原图、路径、问题正文或密钥。
- 可替换：视觉分类器和 Qwen Provider 通过稳定接口解耦，适配决赛国产平台时不重写业务协议。

### 2.2 总体架构

交互链路为：用户任务与可选图片 → Gradio/FastAPI → 输入安全校验 → Qwen3.6-27B 结构化任务计划（失败时确定性回退）→ `WaterAnalysisAgent`本地白名单执行器 → 四折 YOLO-CLS视觉工具、类别知识工具、复核策略工具 → Qwen报告生成或本地回退 → 脱敏 SQLite审计 → 结构化回答。

批量链路为：参赛者显式指定图片目录 → 四折 YOLO-CLS 概率平均 → 官方六类标签映射 → `result.json`与概率审计 → Schema 校验 → 白名单交付构建器。批量链不调用大模型，避免生成随机性和远程服务状态影响打榜结果。

### 2.3 智能体执行流程

1. 接收用户任务与可选图片；有图片时检查扩展名、文件大小、像素数和实际可解码性。
2. Qwen将任务转换为受控JSON计划，例如“识别→类别知识→巡查报告”；本地Pydantic契约只接受白名单意图和工具序列。Qwen不可用或输出非法时使用确定性计划。
3. `WaterAnalysisAgent`本地执行器按计划调用工具。涉及图片时，YOLO分类工具返回六类概率、Top-1、Top-3、模型版本和模型耗时；无图片的类别咨询只调用知识工具。
4. 根据置信度阈值和类别级OOF证据计算复核策略；当前“乱建”和“正常”强制复核。
5. Qwen仅依据不可变的视觉结果、类别知识和复核依据生成简洁分析或巡查报告；不得改写标签、伪造目标框或断言违法事实。关闭thinking以减少空响应和长延迟。
6. 页面展示任务类型、计划来源、执行步骤、工具状态、分类事实、知识依据和最终回答；若Qwen异常，明确展示确定性回退，视觉结论不丢失。
7. 只把请求ID、时间、结构化结论、复核原因、模型版本、耗时和工具状态写入SQLite。

### 2.4 技术栈

| 层次 | 技术 | 选型理由 |
|---|---|---|
| 视觉模型 | Ultralytics YOLO26n-CLS 四折集成 | 与整图六分类标签匹配，小模型适配 8GB 显存，支持统一图片推理接口 |
| 智能体编排 | 自研 `WaterAnalysisAgent` | 工具调用顺序可复现、可审计，不依赖未验证的原生 Function Calling |
| 国产大模型 | 赛事 Qwen3.6-27B OpenAI 兼容接口 | 满足国产开源大模型要求，用于问题理解和结果解释 |
| 服务与界面 | FastAPI + Gradio Blocks | 快速形成可调用 API 和可演示的人机交互界面 |
| 配置与校验 | Pydantic Settings / Schema | 类型安全、环境变量注入、结果协议和上传边界可自动验证 |
| 审计与交付 | SQLite + Python CLI + tar.gz 白名单构建 | 轻量可追溯，提交结构确定且可阻断密钥、缓存和原始数据误打包 |

### 2.5 接口与数据协议

`POST /api/v1/classify`返回视觉标签、置信度、Top-K、复核信息、模型版本和视觉耗时；`POST /api/v1/analyze`在此基础上增加任务计划、自然语言回答、类别知识和完整工具轨迹；`POST /api/v1/consult`支持无图片类别咨询；`GET /api/v1/guidance/{label}`返回受审核类别知识；`GET /health`报告视觉、Qwen、计划器、知识库和审计状态。批量结果每条记录只包含 `filename`、`width`、`height`和`label`，与官方样例保持一致。

## 三、核心模块详细设计

### 3.1 数据审计与分组四折

训练准备首先只读核对 `train.json`和图片，统计标签、宽高、重复与近重复组。衍生折使用独立副本适配 Ultralytics 分类目录，禁止硬链接回原训练图片。近重复图片整体分配到同一折，减少相似画面跨训练/验证造成的泄漏。四折 OOF 要求 1,144 个样本唯一覆盖、无重复、每个样本只使用未见过它的折模型预测。

### 3.2 四折 YOLO-CLS 视觉工具

单折公平对照固定预训练权重、fold、随机种子、图像尺寸、batch 和 epoch，只改变类别损失。类别加权策略在 15 epoch 对照中略优于标准损失，因此四折采用 power=0.5、cap=8 的加权损失。上线推理对四个模型的六类概率做等权平均，再选择 Top-1；温度缩放因 ECE 和 Brier 变差而保持 T=1.0。

模型适配器统一提供 `classify(image)`接口，交互链和批量链均复用同一标签顺序和概率聚合逻辑。模型版本由四个训练运行目录和权重名组成，进入响应与审计记录。

### 3.3 复核策略

基础策略在最高置信度低于 0.65 时提示人工复核。仅靠置信度会忽略验证证据：当前“正常”只有 7 张且 OOF Recall 为 0，“乱建”只有 4 张且 Recall 为 50%，因此这两类无论置信度高低均强制复核。该策略只影响交互提示，不改变赛事批量标签，保证人机安全和打榜确定性同时成立。

### 3.4 Qwen计划与报告工具

Provider按官方案例使用OpenAI兼容`/v1`协议与`qwen3.6-27b`模型。计划Prompt要求只输出四类意图和严格对应的工具序列JSON；本地校验器拒绝非法JSON、未知工具、错误顺序和不符合图片前置条件的计划。报告Prompt要求忠实解释不可变的结构化标签、置信度、类别知识和复核原因，不把大模型当视觉判别器。请求限制问题长度、输出token、超时和有限重试，默认关闭thinking。异常统一脱敏，不在错误信息或日志中暴露密钥、Authorization头或服务响应正文。

赛事提供的 Qwen3-VL-Embedding-8B 和 Qwen3-VL-Reranker-8B 可在后续用于合规案例库的图文检索与重排；首版未把它们置于核心链路，避免在缺少案例库和时间有限时引入不可验证复杂度。

### 3.5 API、界面与输入安全

FastAPI负责健康检查、直接分类、Agent分析和类别咨询；Gradio提供图片上传或无图片咨询、任务描述、分析按钮、回答、分类/置信度、复核原因、Top-3、任务计划、类别知识与工具轨迹。上传同时检查扩展名和真实解码，限制20MB、4,000万像素，临时文件在成功与异常分支均清理。服务面向低并发辅助分析，不在首版宣称生产级高吞吐。

### 3.6 脱敏审计

SQLite只保存 request_id、created_at、label、confidence、requires_review、review_reason、model_version、total_latency_ms和trace_json。数据库不设置 prompt、question、answer、image、path、API Key或Authorization字段。审计目录不可写时服务安全降级，核心识别不被可选存储阻断。

### 3.7 批量提交与白名单交付

批量 CLI 只有在参赛者显式填写输入目录时才读取图片，拒绝覆盖已有结果，生成 `result.json`与概率审计文件。提交校验器检查顶层数组、字段类型、六类枚举和文件名重复。交付构建器要求显式 `--confirm-real-result`，只复制列明的源码、配置、文档、测试、脚本和四折权重；归档前验证 `code/`、`design/`、`result/result.json`，不包含训练/测试图片、密钥、`.env`、缓存和内部日志。

## 四、创新点设计

### 4.1 从“模型能力”到“业务可用能力”

作品的创新不在于让大模型猜图片，而是把已验证的视觉算法变为可由自然语言触发的受控工具。普通用户不需要理解权重、GPU和推理命令，同时保留模型决策的确定性和证据链。

### 4.2 Qwen计划与本地白名单执行

作品不依赖未验证的远程Function Calling。Qwen先提出受约束的JSON任务计划，本地执行器再决定是否调用YOLO识别、类别知识、复核策略和报告工具。用户能够看到“任务理解—执行步骤—工具状态—证据—结论”的外显过程；该过程不是模型隐式思维，也不允许大模型调用任意文件、Shell或网络工具。

### 4.3 智能体链与打榜链同源解耦

交互链利用 Qwen 提升可理解性，批量链绕过大模型保证稳定；两者共享视觉模型、Schema和标签映射，既体现行业智能体价值，又避免为展示单独维护一套与打榜不一致的模型。

### 4.4 类别验证风险驱动的人机协同

系统不是机械使用单一置信度阈值，而是把 OOF 样本量和逐类 Recall 转化为运行时复核策略。尤其对“正常”和“乱建”主动暴露证据不足，减少大模型把统计上不可靠的判断包装成确定结论。

### 4.5 可观测的故障降级

每一步工具均记录 success、fallback 或 disabled。Qwen 服务故障不会覆盖或吞掉 YOLO 结论，审计故障也不会阻断核心识别。演示时可以明确证明系统不是依赖一次理想远程调用的静态样例。

### 4.6 安全交付即代码

最终归档不采用人工排除，而采用白名单复制、Schema验证、敏感文件名扫描、文件哈希清单和真实结果显式确认。把容易遗漏的参赛合规要求固化为可重复执行的构建流程。

## 五、效果评估

### 5.1 模型评估结果

四折分组 OOF 完整覆盖官方 1,144 张训练图片。以下指标来自训练集交叉验证，不是初赛测试集或榜单成绩。

| 指标 | 结果 | 解释 |
|---|---:|---|
| Accuracy | 97.73% | 受多数类影响明显，仅作整体参考 |
| Balanced Accuracy | 71.11% | 六类 Recall 等权平均，更能反映长尾能力 |
| Macro-F1 | 73.43% | 六类 F1 等权平均，是内部选型核心指标 |
| Top-2 Accuracy | 98.95% | 可用于人工复核界面展示候选类别 |

| 类别 | 正确数/真实数 | Recall |
|---|---:|---:|
| 乱采 | 24/24 | 100% |
| 乱建 | 2/4 | 50% |
| 乱堆 | 19/23 | 82.61% |
| 乱占 | 57/60 | 95% |
| 有漂浮物 | 1016/1026 | 99.03% |
| 正常 | 0/7 | 0% |

### 5.2 任务执行耗时

Phase 4 在 RTX 4070 Laptop 8GB 上进行真实现场验收，使用同一训练来源验证副本重复请求：

| 场景 | 现场结果 |
|---|---:|
| 热态单图视觉模型中位耗时 | 82.77 ms |
| 热态分类 HTTP 中位耗时 | 90.39 ms |
| 真实 YOLO + Qwen 端到端中位耗时 | 1,491.46 ms |
| Qwen 解释耗时范围 | 1,178–1,702 ms |
| SQLite 审计单次耗时范围 | 7.7–9.8 ms |
| 3 并发分类 | 全部成功，单请求约 395–530 ms |

单进程工作集约 1.32GiB、私有内存约 3.53GiB。系统采样时总 GPU 显存占用约 1,377/8,188MiB，但 Windows 驱动未提供单进程拆分，因此不把该数值全部归因于本服务。

### 5.3 系统验收

FastAPI的health、classify、analyze、consult与无效上传路径通过；Qwen的真实任务计划与报告生成协议均已安全验证。Qwen故障降级、非法计划回退、SQLite脱敏字段、Gradio类别咨询回调和浏览器页面结构均通过。页面可明确展示任务计划、知识依据和工具轨迹。当前升级质量门为Ruff全绿、51项pytest通过、`pip check`无冲突。

### 5.4 结论与迭代方向

升级版已打通“自然语言任务—Qwen受控计划—本地多工具执行—YOLO视觉事实—复核策略—Qwen报告/本地回退—脱敏审计—官方结果交付”。主要短板仍是极少样本类别，尤其“正常”0 Recall。后续应优先补充可公开追溯且合规的少样本数据，采用类均衡采样、困难样本挖掘和分布漂移评估；在官方允许和案例库具备来源记录后，再启用VL Embedding/Reranker做相似案例辅助。任何扩展都继续保留人工复核、测试集隔离和可追溯交付边界。
